# Lyrics Next 格式规范第二版 第三次修正

> [!note]
> 仅供娱乐，当然如果你的软件想使用这个格式是完全可以的（真的会有人用吗？）

一种基于 [LRC](https://zh.wikipedia.org/wiki/LRC%E6%A0%BC%E5%BC%8F) 的按节拍划分歌词格式，参考了 [TTML](https://en.wikipedia.org/wiki/Timed_Text_Markup_Language)、[Lyricify Syllable](https://github.com/WXRIW/Lyricify-App/blob/main/docs/Lyricify%204/Lyrics.md#lyricify-syllable-%E6%A0%BC%E5%BC%8F%E8%A7%84%E8%8C%83) 和 [Apple Syllable](https://help.apple.com/itc/videoaudioassetguide/#/itc0f14fecdd)  
Lyrics Next 为了解决普通 TTML 歌词可读性差、难以直接编辑的问题而诞生  
Lyrics Next 歌词文件可以直接使用 `lrc` 后缀，也可以使用单独的 `lrcn`

## 更改

相较于原本的 Lyrics Next 第一版，*Lyrics Next 第二版* 进行了许多更改。  
我们认为读者已经了解第一版的特性，故下列变更会基于第一版的改动进行描述。

- 对头部信息进行了精简和变更，使其更适配 Apple Music 新特性
- 将 `end` 标签统一为同步多媒体集成语言（SMIL）表示
- 将 `agent`改用更统一的标签抽象格式
- 新增 LRCN Trans 翻译格式
- 改进了内嵌翻译及发音的方式
- 大幅修改了特殊歌词的格式，使其更适配 Apple Music 新特性

## 规范用语

### 时间标签

在 Lyrics Next 中，歌词行行首被 `[]` 包裹的内容被称为 `行标签`，后续的歌词内容被称为 `正文` 
正文中被 `<>` 包裹的内容被称为 `按节拍划分标签`  

标签中可以被 `:`(仅限头部信息) 或 `,` 分割  
头部信息的划分规范是 `[key:type@value]`，其中 `key` 为标签名，`type` 为标签类型 (可省略)，`value` 为标签值  
时间标签的划分规范是 `[start,end,agent,line]`，具体含义请参考 [歌词](#歌词) 部分  
在标签中被分隔符分割的内容被称为 `元素`  

凡事使用时间轴标记的内容均可称为 `对象`，包括行，字，词或音节  

### 歌曲对唱关系

根据音乐中常见的演唱方式，歌词分为 `主唱(人声/歌词)` 与 `背景(人声/歌词)`  

- 主唱: 常规的 `agent` 均为 `主唱人声`，属于歌词正文，用于主要歌词  
- 背景: `agent` 带有 `x-bg` 字样为 `背景人声`，一般用于背景声。

背景人声的歌词位于主唱歌词下方，字体较小，该歌词行称为 `背景人声` `背景行` `bg 行`

## 头部信息

歌词头部可选的包含歌词相关信息，如：

| 标签                      | 含义                                                     |
| ------------------------- | -------------------------------------------------------- |
| [Lyrics Next]             | Lyrics Next 格式声明                                     |
| [version:2.3]             | 格式版本声明                                             |
| [ti:Da Capo]              | 歌曲名称                                                 |
| [ar:HOYO-MiX]             | 艺术家                                                   |
| [al:Native]               | 专辑                                                     |
| [timing:syllable]         | 项目类型<br>`line` 为逐行，`word` `syllable` 为逐字/节拍 |
| [lang:zh-CN]              | 主要语言                                                 |
| [songwriter:HOYO-MiX]     | 制作人名称                                               |
| [songwriter:车子玉]       | 同上                                                     |
| [agent:person@v1]         | `agent` 对应信息                                         |
| [agent:group@v2]          | 同上                                                     |
| [platform:NCM@2026565329] | 平台 ID                                                  |
| [by:MiaowCham]            | 歌词制作者                                               |
| [offset:0]                | 歌曲偏移量（单位毫秒）                                   |

若一个标签有多个内容，可以用 `,` 分割或者使用多个标签表示

### 解析与省略

该内容可以不填，不要包含重复标签。(重复标签指完全相同的标签)  

若使用 `.lrc` 后缀，格式与版本声明标签必须保留  
若希望得到完整的类 Apple Syllable 体验，需填写 `songwriter` `agent` 对应信息  
若不填入 `agent` 对应信息，则正文不得使用 `agent` 标签

`offset` 标签用于标记歌词的偏移量，解析器应当进行解析与偏移操作。  
允许使用 `[offset:platform@value]` 的方式标记不同平台的偏移量，解析器应当根据平台进行选择性解析。

## 歌词

Lyrics Next 歌词的标准格式为：

```lrcn
[start,end,agent,line]<start,end>Word <start,end>word
```

- `start` 为起始时间，其时间戳使用同步多媒体集成语言（SMIL）表示。  
    一般情况下使用 SMIL 表示，可提供完整或部分时钟值：  
    `hh:mm:ss.sss（时:分:秒.毫秒）`  
    *其中，小时和毫秒可不提供。*  
- `end` 为结束时间，其时间戳使用同步多媒体集成语言（SMIL）表示。  
    *该元素可以省略，若不存在则将后一个项目的开始时间作为结束时间。*
- `agent` 用于标记该句演唱歌词的艺人的 ID。  
    每一位演唱者都应该被分派到一个ID。  
    *该元素可以省略，若只有一个演唱者可以不填。*
- `line` 歌词的行 ID，推荐格式为 `Lx`，如 `L1` `L2`。  
    虽然行 ID 的格式允许自行决定，但不允许使用 `x-bg`、纯数字或类似 SMIL 的 ID  
    *该元素可以但不建议省略，可能影响翻译和发音的解析*
- `<>` 中的时间戳为后方单词的起始时间和结束时间。

### 省略机制

为兼容 LRC 与 增强型LRC 格式，*Lyrics Next 第二版* 要求允许对额外扩展的元素进行省略。  
因此，Lyrics Next 格式是 LRC 与 增强型LRC 格式的超集，所有标准的 LRC 与 增强型LRC 格式均为合法的 Lyrics Next 格式歌词

#### 行元素中，*Lyrics Next 第二版* 额外扩展了 `end`、`agent` 和 `line` 元素，允许进行以下类型的省略：

- `[start,end,,line]`（只省略 `agent` 元素，单一演唱者时可以使用）
- `[start,,agent,line]`（只省略 `end` 元素）
- 同理可以省略 `line` 元素 (带着逗号一起)，但不建议省略，可能影响翻译和发音的解析  
  `[start,end,agent]` `[start,end]` `[start,,agent]`
- `[start]`（全部省略，LRC 格式）

为了保持格式完整，只省略中间元素时，必须保留逗号，  
省略结尾元素时，逗号可以一并省略。

省略 `end` 元素时，解析应当遵循:

- 有按节拍划分的，将本行最后一个节拍的结束时间作为结束时间
- 逐行的，以下一行的开始时间作为结束时间

#### 按节拍划分标签中，*Lyrics Next 第二版* 额外扩展了 `end` 元素，允许省略为：

- `<start>`（全部省略，增强型 LRC 格式）

一行首个节拍可以省略按节拍划分标签，则该节拍的开始时间为行标签的开始时间，结束时间为下一节拍的开始时间 (兼容增强型 LRC)

### 逐句歌词  

如果想使用 Lyrics Next 记录逐句而非按节拍划分歌词，则无需逐词标记时间信息：

```lrcn
[start,end,agent,line]Lyrics
```

> 同样的，你可以根据 [省略机制](#省略机制) 对行标签的元素进行省略，但这样的话和普通 LRC 区别在哪？

### 歌曲结构段落

可以在行之间添加 song-part 标签，用于标记这部分歌词在歌曲结构中的作用。格式如下：

```lrcn
[song-part]            # 简写格式
[start,end,song-part]  # 完整模式
```

推荐使用以下值：

- Verse（主歌）
- Chorus（副歌）
- PreChorus（预副歌）
- Bridge（桥段）
- Intro（前奏）
- Outro（尾奏）
- Refrain（叠句）
- Instrumental（器乐）

> 歌曲组成部分的标记信息当前不向用户显示。  
> 解析器无需对其进行解析，或者是完整展示歌词时仅作为段落分隔参考。

### 背景人声

背景人声必须在主唱歌词下方，具体格式如下：

```lrcn
[start,end,agent,line]<start,end>Word <start,end>word  # 主唱歌词
[x-bg]<start,end>Word <start,end>word                  # 背景
```

> [!note]
> 即使背景人声的起始时间在主句前面，背景人声也得在主句的后一行

## 附属歌词

包括翻译、发音信息，这些内容均视为主歌词的附属歌词  

注意，在使用 LRC 或其他不带有 `line` 标签的格式时，`start` 标签必须和原文的开始时间一致。若存在多句共用完全相同的开始时间，则按照上下顺序对应。背景人声也支持对应。

### 关于 LRCN Trans 格式

是一种基于行 ID 进行精准对应歌词的格式，文件可以直接使用 `lrc` 后缀，也可以使用单独的 `lnt` 后缀

> [!Warning]
> 若主歌词省略了 `line` 标签，则 ***不允许*** 使用 LRCN Trans 格式

支持以下格式：

```LRCN Trans
[start,line]翻译  # 完整格式
[line]翻译        # 仅行数
[x-bg]翻译        # 背景人声
```

按节拍划分的发音歌词：
```LRCN Trans
[start,line]<start,end>Word <start,end>word  # 完整格式
[line]<start,end>Word <start,end>word        # 仅行数
[x-bg]<start,end>Word <start,end>word        # 背景人声
```

### 翻译及行发音

#### 内嵌：在包含多份歌词内嵌时，支持以下格式进行标记不同的歌词文件：

```lrcn
[type: format@value]
```

- `type` 为歌词类型。  
    `lyrics` 对应主歌词，`translate` 对应翻译，`transliteration` 对应发音
- `format@value` 标记歌词的格式。推荐使用的值：
  - `LRC` 对应 LRC 格式
  - `LRCN` `Lyrics Next` 对应 Lyrics Next
  - `LNT` `LRCN Trans` 对应 Lyrics Next 翻译/发音
  - `ESLRC` 对应 ESLRC 格式
  - `Enhanced LRC` 对应增强型 LRC 格式

> [!note]
> 标记歌词格式的实际名称可能会变动，解析器应当进行宽容判断与格式猜测。

完整的歌词文件结构参考：

```
# 头部信息
[Lyrics Next]
[version:2.3]
...

# 主歌词
[lyrics: format@Lyrics Next]
[start,end,agent,line]<start,end>Word <start,end>word
...

# 翻译歌词 (完整格式)
[translate: format@LRCN Trans]
[start,line]翻译
...

# 发音歌词 （LRC 格式）
[transliteration: format@LRC]
[start]翻译
...

# 按节拍划分的发音歌词 (仅行数)
[transliteration: format@LRCN Trans]
[line]<start,end>Word <start,end>word
...
```

> [!note]
> 但凡内嵌翻译和(或)发音的歌词文件，必须进行格式标记。纯 LRCN 可不包含格式标记

#### 外置：为了满足 i18n 需求，建议尽可能使用外置翻译/发音。  
外置翻译/发音文件应当是 LRC 或 LRCN Trans 格式文件，具体格式如下：

```lrc
[translate: format@LRC]   # 声明类型
[lang:zh-CN]              # 声明语言
[start]内容
...
```

> [!note]
> 外置方案是将翻译/发音单独存放文件，通过文件名或专辑元数据文件进行关联。  
> 关于关联方式，不属于本格式规范范畴，可以参考 [Apple Music 技术规范](https://help.apple.com/itc/musicspec/#/itccdd938379)。 

若配置了曲目元数据文件，声明可以省略
